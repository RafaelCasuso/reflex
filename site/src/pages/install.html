Install, in two minutes.

One command installs rfx; one command installs REFLEX into a project. It starts in Observe: it records what your agent does and changes nothing, until you decide.

Requirements

  • Node.js 24 or later, and npm.
  • Claude Code or Codex. REFLEX detects the ones you have; with neither detected it still installs the Claude Code hook, for when you have it.

The command

{{install.command}}

Run the second half, rfx init, inside the project you want governed. The repository's continuous integration runs this exact line against the released package before every change to this page is published.

What rfx init does

It shows its plan and does nothing until you confirm. This is a real plan, on a machine with both hosts:

{{{captures.init.html}}}
  1. It detects the hosts you have.
  2. It backs up every file it is about to change, under ~/.reflex/backups.
  3. It adds one hook per event to the host's settings. Your own hooks stay; REFLEX's are the only ones it adds or ever removes.
  4. It writes a conservative starter policy to .reflex/policy.yaml when the project has none, and trusts it as written.
  5. It creates an anonymous local identity. It is random and never sent anywhere.
  6. It starts in Observe. The hooks answer nothing to the host.

Switching it on

rfx mode assist lets REFLEX allow what the policy allows and hands everything uncertain to the host's own prompt; it never blocks. rfx mode autopilot enforces allow, ask and deny. Both read the policy you can see with rfx explain; rfx mode observe goes back.

When something is off

rfx doctor checks the install, the hooks and the host's own switches, the daemon, the policies and their trust, the provider and its consent. Every failure names what to do:

{{{captures.doctor.html}}}

Taking it back

rfx uninstall removes REFLEX's hooks, byte for byte when the file is unchanged since, surgically otherwise, and leaves a file another project still uses. rfx uninstall --purge also deletes ~/.reflex: your observations, backups and identity.
